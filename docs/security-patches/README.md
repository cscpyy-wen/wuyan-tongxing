# 维护者安全补丁：来源、验证与发布边界

本目录不是忽略漏洞的白名单。2026-10-22，维护者明确选择在无上游正式修复版本时，公开本地补丁并验证后再发布。npm/OSV 的原始警报仍保留，不能称为“扫描零告警”。发布要求是 **low 阈值下没有未处置项**，且下面每一项实际校验都成功。

## 当前补丁

- [braces 3.0.3](braces.md)：限制深度与父链遍历；保留原 npm 身份、MIT 和上游 tarball 完整性。
- [http-cache-semantics 4.3.0](http-cache-semantics.md)：响应限制优先于过期复用；4.3.0 上游版仍可复现本问题，不能仅凭扫描器版本范围说已修复。保留 BSD-2-Clause。
- [精确证据清单](manifest.json)：补丁、上游完整性、回归程序、全部安装文件、通告修订及复核截止日期。清单变化必须人工重新审查，禁止从未知新安装结果自动接受哈希。

## 检查如何阻止误放行

`pnpm verify:security-patches` 不读取缓存的“通过”标记，而是每次：

1. 检查复核期（最多 31 天）、workspace 与锁文件精确补丁集合、原始 tarball 完整性和锁定补丁哈希。
2. 检查补丁文件与回归入口的字节哈希，拒绝路径越界。
3. 拒绝未修补或未审阅版本的锁快照；遍历完整安装依赖图，包括别名和开发依赖，检查每个实际副本的完整文件集合与逐文件哈希。
4. 针对每个已校验副本重新执行离线回归；超时、非零退出、零用例、数量不足、失败、跳过或待办均不能通过。

`pnpm audit:all` 仍实时查询根生产图、根完整图和 CloudBase 独立图，均使用 `low`，不改动工作树。准备发布时先以 `pnpm audit:all --write-report` 保存原始结果于 `docs/dependency-audit.json` 并提交；正式构建再实时重查，不能以旧报告代替。任何新通告、未知版本、公告事实变化、计数不一致、网络或解析失败均阻止发布。一个通告只有匹配已审阅事实、且上面实际补丁检查通过时，才会标记 `fixed-by-verified-local-patch`。

OSV 保留原始 `findingCount` 与 `findings`；另列 `assessment`，不将已修补的原始记录删除。上游 PURL 和版本不会加上 pnpm 的 `patch_hash` 后缀；SBOM 的上游 tarball 哈希与本地补丁哈希分别标注。扫描返回尚未读取的分页时失败关闭。正式包构建实时重查报告，并验证报告不超过 24 小时、SBOM 字节一致、补丁证据一致；APK 交付核验再次重算处置结果，不能只写一个 `unresolvedFindingCount: 0` 就放行。

复核期到期后，应检查上游发布和通告变化、重新审查并运行全部验证，再提交新的精确清单；不能机械延长日期。上游发布兼容的正式修复后，优先迁移并移除本地补丁。

## 不能推导的结论

这些是针对已知问题、固定依赖版本的维护者修补，不是第三方安全认证，也不证明没有其他漏洞。braces 的深度保护不是通用 AST 类型校验或输出数量/内存预算。缓存模块的范围与兼容差异见其专题文档。Android 不申请联网权限，不等于可以忽略构建链风险。旧候选 APK 的真机反馈不自动覆盖依赖更新后重建的新包。
