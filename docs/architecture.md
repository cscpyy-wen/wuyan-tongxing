# 技术架构

## 运行目标

当前主要用户产品为 **Android 本地 App**。`apps/client` 提供随包运行的页面、记录和无烟首页，`apps/android-shell` 通过 Capacitor 与原生代码提供持久化、桌面小组件、控制中心快捷入口、本地提醒和 JSON 备份恢复。APK 不申请 `INTERNET` 权限，不依赖登录或 API；权限约束由制品校验继续执行。

其余路径与 Android 交付分开维护：

1. **内部测试**：H5 与微信开发者工具测试模式，使用本地 API、PGlite 和模拟微信身份/订阅消息。
2. **正式微信环境**：需要真实主体、AppID、境内备案域名、云资源和订阅消息模板。没有这些条件时，任何模拟结果都不能标记为真实微信集成通过。
3. **免登录静态工程预览**：`deploy/tencent-cloudbase` 提供静态包构建与托管辅助，不连接 API。它用于工程与可用性验证，不是 Android 用户下载入口；是否对外可访问取决于实际托管配置，不能因构建成功就称已公开上线。
4. **HarmonyOS 实验适配**：复用客户端和本机持久化接口，能力由平台适配声明；不能把 Android 的备份恢复、通知或系统快捷入口能力直接推定为 HarmonyOS 已实现或已上架。

## 模块

| 模块 | 职责 | 可接触个人戒烟记录 |
|---|---|---|
| `apps/client` | Android 随包页面及其他平台客户端、离线记录、无烟首页、规则执行、SOS | 是，当前客户端只在本地处理 |
| `apps/android-shell` | Android 原生容器、私有持久化、小组件、控制中心、提醒和备份恢复 | 是，仅本机；用户可主动导出文件 |
| `apps/api` | 实验身份、同步、提醒意图、统计、导出/删除 | 接收请求时处理敏感字段并加密存储；不得写入日志；未与当前 Android 接通 |
| `apps/worker` | 幂等提醒与延迟删除任务 | 仅任务所需的最小标识 |
| `apps/admin` | 内容、证据、规则、发布和聚合指标 | 否，不提供个人记录查询接口 |
| `packages/domain` | 戒烟状态机、日期和统计公式 | 纯函数，不联网 |
| `packages/rules` | 白名单规则 DSL 与确定性决策 | 客户端执行，不上传健康输入 |
| `packages/content` | 版本化循证草案内容包 | 不含用户数据 |
| `packages/platform` | 身份、存储、提醒、分享适配器 | 按适配器最小化 |
| `packages/persistence` | API/Worker 共用的幂等 PGlite 内部测试 schema | 不直接读取用户数据 |
| `deploy/public-preview-site` | 把公开免登录 H5 固化进单一 Worker，并统一施加安全响应头 | 戒烟记录只由浏览器本地客户端处理；托管层仍处理普通网络元数据 |

## 本地优先数据流

1. 首次进入先确认成人身份，再单独同意处理戒烟自我管理所需的敏感健康信息。
2. 计划、记录、任务和 SOS 写入客户端本地存储，不要求登录或联网。Android 核心档案通过原生桥接写入应用私有的非备份目录，使用原子写入、写后校验及最后有效副本；格式不合法时进入恢复流程。
3. 规则引擎读取本地结构化状态并返回内容 ID、原因码和证据 ID；输入不发送到服务端。
4. Android 隐藏云同步和统计开关，不调用 API；其他实验客户端的云同步、统计和订阅开关只记录本地模拟状态，因此拒绝或开启都不会产生网络上传。
5. 正式接线后的目标流程才是：用户主动开启云同步后交换微信身份并通过幂等队列同步；另行开启统计后才发送白名单事件，且 `analytics_id` 不得与 OpenID 联表。该目标流程已有独立 API 契约和服务端测试，但尚未完成客户端集成。

v34 在现有 v1 档案中增加可选 `quitJourney`，保存主动确认的无烟起点和独立估算参数。缺少该字段的旧档案仍可读取；保存前先处理快捷记录队列，避免未归并的吸烟事实被跳过。无烟时长、少抽和烟费由原始记录及设备时间重新计算，不改写原始基线或补写历史日终确认。参数和恢复辅助数据随现有 JSON 备份导出；私有目录、备份及恢复数据均不应被描述为应用层加密。完整数据范围见 [隐私与数据地图](privacy-data-map.md)。

## 实验 API 的同步冲突契约

- 日志、烟瘾、滑倒和任务进度按客户端 UUID 幂等追加。
- 删除写入 tombstone，防止离线旧设备把已删除对象重新上传。
- 设置按版本进行乐观并发控制。
- 本地与云端存在不同活动戒烟计划时，API 返回两个版本，由用户明确选择；禁止静默覆盖或自动拼接。

## 内容治理

内容状态固定为：`DRAFT → EVIDENCE_VERIFIED → MEDICALLY_APPROVED → PUBLISHED → RETIRED`。

当前内部测试渠道只接受 `DRAFT` 内容，状态保留在内容包、发布清单和管理后台中。按个人使用者要求，客户端不显示重复的草案/审核状态横幅；这不改变工程审核状态。正式渠道必须同时满足具名审核人、审核日期、证据关联和发布审计。

## 后端正式接线前的替换点

- PGlite → 境内托管 PostgreSQL。
- 本地开发密钥 → 境内 KMS 包封的数据密钥；认证签名、稳定标识派生和数据加密使用彼此独立、可轮换的密钥用途。
- `MockIdentityAdapter` → 服务端 `code2Session` 交换。
- 模拟提醒 → 经审核的微信订阅消息模板。
- 本地静态转介目录 → 有核验日期与下线流程的境内内容服务。

## PGlite 内部运行边界

- PGlite 只用于本机内部测试，按单连接、串行方式使用；API 与 Worker 不得同时打开同一个 `DATABASE_DIR`。
- API 与 Worker 复用 `@wuyan/persistence` 中同一份幂等 schema 初始化，因此任一入口都能初始化全新本地库，不再维护两份 DDL。
- 需要本地验证队列时，先运行并正常关闭 API，再执行一次 `pnpm --filter @wuyan/worker start:once`，完成后再重启 API。
- 上述初始化修复不代表解决了 PGlite 的多进程排他限制。正式环境必须完成 PostgreSQL 适配、迁移与备份恢复后，才能并行运行 API 和常驻 Worker。
- 当前 API 与 Worker 在 `NODE_ENV=production` 下无条件拒绝嵌入式 PGlite 启动；在真正的 PostgreSQL 适配器和生产迁移完成前，不存在可绕过的“临时生产模式”。
